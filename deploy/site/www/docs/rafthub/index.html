Héberger son propre Rafthub

Rafthub gère les comptes, les amis et la présence des joueurs. Le vôtre tourne sur votre serveur, ou même sur votre PC, pour votre communauté.

Version auto-hébergée : connexion par pseudo ou e-mail, et mot de passe. La connexion avec Discord est réservée au Rafthub officiel. Rafthub est sous licence AGPL-3.0 : si vous modifiez son code et l'ouvrez à d'autres, vous devez publier vos changements.

1. Télécharger et lancer

Sur la page des releases, prenez l'archive de votre système :

  • rafthub-linux-x86_64.tar.gz pour Linux (64 bits) ;
  • rafthub-windows-x86_64.zip pour Windows.

Décompressez-la dans le dossier où vivra le hub, puis lancez-le :

./rafthub

Par défaut, le hub écoute sur 127.0.0.1:8787. Il range ses données dans un dossier rafthub-data/, créé à côté de l'exécutable : base, réglages et cache.

2. L'assistant d'installation

Au premier lancement, le hub n'a ni base ni administrateur. Il écrit dans son journal un code d'installation :

premier lancement : ouvrez /admin dans un navigateur, code d'installation 7K2M…

Ouvrez ensuite http://127.0.0.1:8787/admin dans un navigateur, et suivez les deux étapes :

  1. Choisir la base de données :
    • base intégrée (SQLite) : rien à installer, le bon choix pour un groupe d'amis ;
    • base externe : PostgreSQL, MySQL ou MariaDB, avec l'adresse, le nom de la base, l'utilisateur et le mot de passe.
    Le hub essaie la connexion avant de garder votre choix.
  2. Créer le premier administrateur : e-mail, pseudo et mot de passe. Le code n'est demandé qu'une fois.

Le code prouve que vous avez accès au serveur : sans lui, personne ne peut prendre la main sur un hub tout juste installé. Il change à chaque redémarrage tant qu'aucun admin n'existe. Installez donc le hub juste après l'avoir lancé.

Ensuite, la console /admin vous donne :

  • Réglages : nom du hub, inscriptions (ouvertes, sur invitation ou fermées), serveur d'e-mails (SMTP) ;
  • Joueurs : liste, recherche, suspension, codes d'invitation ;
  • Distribution du launcher : un launcher prêt à se connecter à votre hub ;
  • Journaux : les actions des administrateurs.

D'autres admins ? Créez leur compte normalement, puis :

rafthub admin create joueur@exemple.org

3. Ouvrir le hub à Internet

Le launcher n'accepte un hub distant qu'en HTTPS. Il faut donc un nom de domaine (par exemple hub.exemple.org) qui pointe vers votre serveur, puis l'une de ces trois façons de faire :

ModeOptions
Derrière un proxy (Traefik, Caddy, nginx) qui fait le HTTPS--listen 127.0.0.1:8787 --public-url https://hub.exemple.org
HTTPS avec vos fichiers de certificat--tls-cert fullchain.pem --tls-key privkey.pem
HTTPS automatique avec Let's Encrypt--listen 0.0.0.0:443 --tls-acme hub.exemple.org
  • Let's Encrypt : le hub obtient et renouvelle son certificat tout seul. Il doit être joignable sur le port 443. Essayez d'abord avec --tls-acme-staging (serveur d'essai), puis retirez l'option. --tls-acme-email donne une adresse de contact à Let's Encrypt.
  • Vos fichiers : par exemple ceux de certbot. Redémarrez le hub après chaque renouvellement.
  • Console à part : --admin-listen <adresse:port> sert la console /admin sur une autre adresse, par exemple celle d'un VPN ou du réseau local. Sur l'adresse publique, /admin répond alors 404. Conseillé pour un hub ouvert à tous.

Les secrets passent mieux par l'environnement que par la ligne de commande : RAFTUP_HUB_DB, RAFTUP_HUB_SMTP_URL, RAFTUP_HUB_MAIL_FROM. Le plus simple reste de régler le SMTP dans la console, qui ne réaffiche jamais un secret. rafthub --help liste toutes les options.

4. Avec Docker et Traefik

Le dossier deploy/rafthub/ du dépôt contient un déploiement complet : image du hub, conteneur sans droits en lecture seule, labels Traefik, et un service de sauvegarde nuitière de la base intégrée, avec rotation. En bref :

git clone https://github.com/Yonako25/raftup.git
cd raftup/deploy/rafthub
cp .env.example .env      # domaine, Traefik, adresse privée de la console
mkdir -p backups && sudo chown 10001:10001 backups
docker compose build
docker compose up -d
docker logs rafthub 2>&1 | grep "code d'installation"

Toutes les étapes, la restauration d'une sauvegarde et les conseils de sécurité sont dans son README.

5. Relier les launchers à votre hub

Trois façons, au choix :

  • Un lien : envoyez raftup://hub/hub.exemple.org à vos joueurs. En l'ouvrant, le launcher leur demande de confirmer le changement de hub.
  • Un launcher préréglé : la page Distribution du launcher de la console prépare un zip avec le launcher officiel signé et un fichier rafthub.toml. Au premier lancement, le launcher adopte votre hub. Vous pouvez proposer ce zip sur la page publique /telecharger de votre hub.
  • À la main : chaque joueur tape l'adresse https://hub.exemple.org en bas de l'écran « Amis ».

6. Sauvegarder

  • Base intégrée : tout est dans rafthub-data/. Copiez rafthub.db hub arrêté, ou utilisez sqlite3 rafthub.db ".backup copie.db" hub en marche.
  • Base externe : utilisez l'outil du moteur (pg_dump, mysqldump). Gardez aussi rafthub.toml, qui contient l'adresse de la base et son mot de passe : il est secret.
  • Gardez une copie hors du serveur : une sauvegarde sur le même disque ne protège pas d'une panne de disque.
